# 0.1.2 upgrade fixtures

Source: git tag `0.1.2`, commit `81ea56490773b9da952381f6bd4c7db72ec93151`.

These fixtures are intentionally frozen rather than generated from current defaults or by building/running an old application. Test databases are created with rusqlite in temporary directories, using these historical SQL schemas **before** opening the current engines.

- `preferences.sql`: verbatim `PreferencesEngine::new` CREATE statements from `crates/iceon-core/src/preferences.rs`; preferences schema version 1, plus the separate `route_history` singleton table.
- `preferences-default-macos.json`: field names and literal defaults transcribed from that file's `Preferences`, nested structs, `Default` implementations and camelCase serde annotations. `showTrayIcon=true` is the macOS default; the regression also exercises the false Linux/Windows default. This is the stored preferences payload, not the API snapshot wrapper.
- `preferences-custom.json`: same complete historical field set, with valid nondefault settings to detect accidental reset of every surviving field. Includes explicit tray opt-out, enabled restoration, old hotbar auto-hide, and an old bundled theme.
- `theme-ids.json`: all 19 shipped IDs read from `git show 0.1.2:themes/*.json` (excluding schema and semantic tags). Theme enum identities were generated by the old build script from these IDs.
- `catalog.sql`: verbatim `SCHEMA` from `crates/iceon-core/src/catalog/storage.rs`, schema version 5, followed by the ownership table CREATE statement from `catalog.rs`. The test inserts two metadata-only clusters with the historical SHA-256 identity algorithm, pins and sync ownership without importing through the current engine. No kubeconfig secrets are stored. Missing source files deliberately prove metadata survives without credentials/files being available.
- `app_data_dir.rs.txt`: verbatim historical `runtime::app_data_dir` function, compared statically without mutating process environment or touching real user data.

Intentional compatibility differences checked by these tests: `app.autoHideHotbar` is discarded; retired bundled themes fall back to `system` while `system`/`dark`/`light` remain intact; new `zedTheme` is unset. Catalog pin metadata remains stored but is inert in public projections.

These are core persistence regressions, not an installer/update lifecycle, signed package, OS tray/login, keychain, or live Kubernetes connectivity test. Manual replacement must continue to use the same user data directory (and the same environment overrides). Successful persistence tests do not imply old binaries can read newly saved preferences or that files deleted externally can be recovered.
